# ledkit Milestone 2: `ledkit-core` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver `ledkit-core`: the LED chip catalogue, color orders, per-technique encoders, the `Strip` pixel buffer with its output pipeline (brightness, gamma, correction, power limiting, dithering), blocking and async output traits, and `smart-leds` driver interop. Everything is host-tested; no hardware needed.

**Architecture:** A chip is a zero-sized type implementing `Chip`, which carries its pixel type (`Rgb` or `Rgbw`), wire color order, protocol (clockless timing windows or a clocked frame format) and power model as associated consts. Encoders turn a chip's timing into what a technique needs: RMT/PIO tick counts, SPI bit patterns chosen for the actual SPI clock, or a DotStar frame. `Strip<C, N, O>` owns `N` pixels and an output `O`; `show()` runs the pipeline per pixel (correction → gamma → brightness with optional dithering, after power limiting) and hands processed pixels to `O: Output<C>`. Backends (milestone 3+) implement `Output` using the `wire` and `encode` helpers defined here.

**Tech Stack:** Rust stable, MSRV 1.82, edition 2021, `#![no_std]`, no allocation. Depends on `ledkit-color` (path + version). Optional `smart-leds-trait` 0.3. Dev-dependency `embassy-futures` 0.1 (for `block_on` in async tests).

**Spec:** `docs/superpowers/specs/2026-10-25-ledkit-design.md` (sections "Key design decision: support techniques, not boards", "`ledkit-core`", "API feel", "Notes carried into milestone 2").
**Milestone 1 API used here:** `ledkit_color::{Rgb, Rgbw, GammaTable, GAMMA_2_6, correction}`; `Rgb::corrected(self, Rgb) -> Rgb`; `GammaTable::apply(&self, u8) -> u8`; `From<Rgb> for Rgbw`; feature `smart-leds` gives `From<Rgb> for rgb::RGB8` and `From<Rgbw> for smart_leds_trait::RGBW<u8>`.

## Decisions this plan makes (from the spec's open points)

- **Timing windows, not ±tolerance.** Each phase of a bit (zero-high, zero-low, one-high, one-low) has a typical value plus a min/max window. High-time windows follow datasheets; low-time windows use the datasheet minimum and a generous maximum (5 µs; 10 µs for 400 kHz WS2811), because real chips only care that a low phase is shorter than the reset time. **These values are verified on hardware in milestone 3.**
- **Brightness is perceptual by default (owner-approved).** `strip.set_brightness(0.5)` *looks* half as bright. A `Brightness` stores either a perceived level or an exact level. Perceived levels map to the raw output level through `GAMMA_2_2` when the frame is processed, so `from_fraction(0.5)` gives raw 56. `Brightness::exact(u8)` sets the raw output level with no curve. `strip.set_brightness(0.3)` works through `From<f32>`; `Brightness::from_percent(30)` is also offered. There is no `From<u8>` (it would be ambiguous). Gamma 2.2, not 2.6, is used for brightness so that low settings stay visible: 10% gives raw 2.
- **Colors are sent exactly as typed (owner-approved).** Gamma on colors is opt in: `strip.set_color_gamma(&GAMMA_2_6)` / `clear_color_gamma()`. The Adafruit-tuned named colors were tuned without gamma, and color gamma would turn `Color::ORANGE` almost red. The strip stores `&'static GammaTable`.
- **Dithering is on by default (owner-approved).** At full brightness it has no effect (it's lossless), so it only acts when brightness scaling happens, which is where the coarse low levels show. `set_dithering(false)` turns it off.
- **`Strip::set` ignores out-of-range indexes**, like Adafruit's `setPixelColor`. Idiomatic indexed access is available through `pixels_mut()`.
- **SK9822 uses the same frame as APA102.** The end frame is 4 zero bytes followed by `ceil(n / 16)` zero bytes, which works for both chips. Verified on hardware in milestone 3.
- **`smart-leds` interop direction for this milestone:** any `SmartLedsWrite` driver can be a ledkit output (`SmartLedsOutput`). The reverse direction (ledkit backends implementing `SmartLedsWrite`) is implemented by each backend in milestone 3+.
- **Gaps in usable SPI clocks are real** (for example, WS2813 works at 3.3 and 4.5 MHz but not at 4.0 MHz). So the SPI error reports the nearest working clocks above and below, not a range.

## Review Focus

1. **A WS2812B strip on a common SPI clock must just work.** 2.4 MHz and 3.2 MHz both encode, with no error. A user on 1 MHz gets a clear message suggesting 2.3 MHz. Tests are in Task 4.
2. **Full brightness is lossless, and colors arrive as typed.** A new strip's defaults (full brightness, no color gamma, no correction, dithering on) send every color unchanged. Brightness 0 is exactly black, even with dithering. Tests are in Tasks 6 and 8.
3. **Power limiting never exceeds the limit, and never touches a strip that's under it.** It also handles a limit below the strip's idle current, which gives all-black output and no panic. Tests are in Task 7.
4. **Setting a pixel out of range does nothing** (no panic), and `fill_range` clamps a range that extends past the end. Tests are in Task 8.
5. **RGBW chips accept plain `Rgb` colors** (`strip.set(0, Color::RED)` on an SK6812 RGBW strip compiles, and white = 0). The power estimate counts the white channel. Tests are in Tasks 7 and 8.

  - `pub enum BitPhase { ZeroHigh, ZeroLow, OneHigh, OneLow }`, with `Display` giving "high time of a 0 bit", "low time of a 0 bit", and so on.
  - `pub enum TimingError`:
    - `PhaseOutOfRange { phase: BitPhase, actual_ns: u32, min_ns: u32, max_ns: u32 }`
    - `TooManyTicks { ticks: u32, max_ticks: u32 }`
    - `SpiClockUnusable { spi_hz: u32, nearest_lower_hz: Option<u32>, nearest_higher_hz: Option<u32> }`
  - `impl core::fmt::Display for TimingError` with plain-English messages. Example: "an SPI clock of 1.0 MHz can't produce valid timing for this LED; try 2.0 MHz". Frequencies print in MHz with one decimal place.
  - `pub struct BufferTooSmall { pub needed: usize }` with `Display`.
  - `pub struct PulseTicks { pub zero_high: u32, pub zero_low: u32, pub one_high: u32, pub one_low: u32, pub reset: u32 }`
  - `pub fn ClocklessTiming::pulse_ticks(&self, ticks_per_second: u32, max_ticks: u32) -> Result<PulseTicks, TimingError>`:
    - `ticks = (typical_ns as u64 * ticks_per_second as u64 + 500_000_000) / 1_000_000_000`
    - the actual duration is `ticks * 1e9 / ticks_per_second`, in integer ns, rounded down
    - each phase must be ≥ 1 tick, have its actual ns inside its window (otherwise `PhaseOutOfRange`, checked in the order zero_high, zero_low, one_high, one_low), and be ≤ `max_ticks` (otherwise `TooManyTicks`)
    - `reset` = `reset_us` converted the same way. It isn't window-checked, and it isn't capped by `max_ticks`, because backends split long resets.

### Task 4: SPI encoding

**Files:**
- Create: `src/encode/spi.rs`

**Interfaces:**
- Consumes: `ClocklessTiming`, `TimingError`, `BufferTooSmall` (Tasks 2–3).
- Produces:
  - `pub struct SpiEncoding { pub bits_per_led_bit: u8, pub zero_high_bits: u8, pub one_high_bits: u8, pub reset_bytes: u32 }` (`Copy, Clone, Debug, PartialEq, Eq`)
  - `pub fn ClocklessTiming::spi_encoding(&self, spi_hz: u32) -> Result<SpiEncoding, TimingError>`
  - `pub fn SpiEncoding::buffer_len(&self, wire_bytes: usize) -> usize` = `1 + (wire_bytes * 8 * N + 7) / 8 + reset_bytes`, where `N = bits_per_led_bit`
  - `pub fn SpiEncoding::encode(&self, wire: impl IntoIterator<Item = u8>, out: &mut [u8]) -> Result<usize, BufferTooSmall>`. It returns the number of bytes written. It needs the byte count up front for the `BufferTooSmall` check, so `wire` must be `ExactSizeIterator`: use `impl IntoIterator<Item = u8, IntoIter: ExactSizeIterator>`, or take `&[u8]` if that bound doesn't compile on 1.82.

Selection algorithm (exact). Let `bit_ns(k) = k * 1_000_000_000 / spi_hz` in exact rational arithmetic. Compare with `k * 1e9 <= max_ns * spi_hz` in `u64` to avoid rounding.

```text
best = none
for N in 3..=8, k0 in 1..N, k1 in (k0+1)..N:
    valid if  zero_high.contains(bit_ns(k0)) and zero_low.contains(bit_ns(N-k0))
          and one_high.contains(bit_ns(k1))  and one_low.contains(bit_ns(N-k1))
    score = Σ over the four phases |k * 1_000_000_000_000 / spi_hz (u64 floor) - typical_ns * 1000|   (picoseconds)
    keep the valid candidate with the smallest (score, N, k0, k1)
```

If none is valid, return `SpiClockUnusable` with `nearest_lower_hz` and `nearest_higher_hz`: the nearest frequencies on the 100 kHz grid from 1.0 MHz to 40.0 MHz (inclusive) for which an encoding exists, strictly below or above `spi_hz`.

The output layout: one leading `0x00` byte (it holds the line low, in case MOSI idles high), then each wire byte MSB first. Each LED bit becomes `N` SPI bits: `k` ones followed by `N - k` zeros, with `k = one_high_bits` for a 1 and `zero_high_bits` for a 0. The bits pack MSB-first, straddling byte boundaries. The last partial byte is padded with zeros. Then come `reset_bytes = ceil(reset_us * spi_hz / 8_000_000)` zero bytes.

    1. **Correction:** apply `ledkit_color::Rgb::corrected` to the red, green and blue channels. Its formula is `(v * f + 127) / 255`. Don't re-implement it: build an `Rgb` from the pixel's R, G and B, call `.corrected(s.correction)`, and take the channels back. White is left unchanged.
    2. **Gamma:** if a table is set, apply it to every channel, white included.
    3. **Brightness:** `scale_channel(v, s.brightness, s.dither)` on every channel.

  - `pub fn estimate_microamps<P: Pixel>(pixels: &[P], model: PowerModel) -> u32`: `pixels.len() * idle + (sum of all channel values, white included) * channel_full / 255`, in `u64` with integer division at the end, saturating to `u32`.
  - `pub(crate) fn limited_brightness<P: Pixel>(pixels: &[P], settings: &PipelineSettings, model: PowerModel, limit: Milliamps) -> u8`. It returns 0 if even `b = 0` exceeds the limit, which happens when the limit is below the idle current. For speed, use the estimate at the requested brightness to compute an initial guess `b0 = b * available / channel_part`, then step down one at a time until it fits.

## Post-review amendments (applied in the final fix wave)

The milestone 2 final review led to these changes, which supersede the text above where they differ:

- The WS2812B zero-high window is `400, 220, 450` (was 550), so 1 MHz now suggests 2.3 MHz.
- `wire::clockless_bytes` / `wire::clocked_frame` return named `ExactSizeIterator` types (`ClocklessBytes`, `ClockedFrame`), so they feed `SpiEncoding::encode` directly.
- `spi_encoding`, `buffer_len` and `pulse_ticks` are `const fn`, so buffers can be sized at compile time.
- `Protocol`, `ClockedFormat` and `TimingError` are `#[non_exhaustive]`.
- `Output` and `OutputAsync` were removed from the prelude, and the error types implement `core::error::Error`.
- The power limiter returns the true maximum brightness that fits.
- The `PhaseOutOfRange` message always suggests a faster clock, which is the only fix for a tick-rounding miss.
