# ledkit Milestone 3: `ledkit-spi` (first light) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver `ledkit-spi`, the universal backend that drives NeoPixels (via SPI encoding) and DotStars (natively) from any `embedded-hal` 1.0 SPI bus, blocking and async, and light a real LED with it: the ESP32-C6 DevKit's onboard WS2812.

**Architecture:** Two output types, one per technique. `ClocklessSpi<C, SPI, B>` encodes processed pixels into a byte buffer `B` with an `SpiEncoding` chosen at construction for the real SPI clock, then writes the buffer in one transfer. `ClockedSpi<C, SPI>` streams a DotStar frame through a small stack chunk, so it needs no buffer. Both implement `ledkit_core::Output` / `OutputAsync` (for `Strip`) and, with the `smart-leds` feature, `SmartLedsWrite` / `SmartLedsWriteAsync`. A chip of the wrong kind is a compile error. `ledkit-core` gains a byte-aligned SPI encoding search and a streaming encoder. Examples are standalone projects outside the workspace.

**Tech Stack:** Rust stable, MSRV 1.82, `#![no_std]`, no allocation. `ledkit-core` (path + version), `embedded-hal` 1.0, `embedded-hal-async` 1.0, optional `smart-leds-trait` 0.3. Dev-dependency `embassy-futures` 0.1. Examples: `esp-hal` 1.x (ESP32-C6, `riscv32imac-unknown-none-elf`, flashed with `espflash` 4.x) and `linux-embedded-hal` (Raspberry Pi).

**Spec:** `docs/superpowers/specs/2026-10-25-ledkit-design.md` (sections "Key design decision: support techniques, not boards", "Crates" → `ledkit-spi`, "Decided: who sets up the hardware", "Hardware scope", "Test hardware"). **Roadmap notes this plan answers:** `docs/superpowers/plans/2026-10-25-ledkit-roadmap.md`, "Notes for the milestone 3 plan".

**Milestone 2 API used here** (read `crates/ledkit-core/src/` for exact docs):
- `Chip` (`type Pixel`, `ORDER: ChannelOrder`, `PROTOCOL: Protocol`), `ChannelOrder::len() -> usize` (const)
- `ClocklessTiming::of::<C>()` (const; panics for clocked chips), `ClocklessTiming::spi_encoding(&self, u32) -> Result<SpiEncoding, TimingError>` (const)
- `SpiEncoding { bits_per_led_bit, zero_high_bits, one_high_bits, reset_bytes }`, `buffer_len(&self, wire_bytes) -> usize` (const), `encode(&self, wire: impl IntoIterator<Item = u8, IntoIter: ExactSizeIterator>, out: &mut [u8]) -> Result<usize, BufferTooSmall>`

- `interop::SmartLedsColor` (`type Color`, feature `smart-leds`); `ledkit-color` gives `From<RGB8> for Rgb` and `From<RGBW<u8>> for Rgbw`

## Decisions this plan makes

- **Byte-aligned encoding is the default.** Blocking SPI drivers on many HALs (esp-hal refilling its 64-byte FIFO, STM32, some SAMD) leave idle gaps between bytes. In an encoding with 3, 5, 6 or 7 SPI bits per LED bit, a gap can land in the middle of a high pulse and stretch it. With 4 or 8 bits per LED bit, every byte ends in a low phase, so a gap only stretches a low time (harmless below the reset time). `ClocklessSpi::new` uses the byte-aligned search; `ClocklessSpi::new_packed` uses the full search, for gap-free (DMA) buses only.
- **The user passes the actual SPI clock rate** they configured. HALs round the requested rate; the docs say to pass the real rate when the HAL reports one. The recommended clock for the WS2812/SK6812 family is 3.2 MHz: it is exact on ESP32 (80 MHz ÷ 25) and has plenty of tolerance either side.
- **The clockless buffer is supplied by the user** as any `B: AsMut<[u8]>` (an array by value, `&mut [u8]`, or `&'static mut [u8; N]`). `ledkit_spi::buffer_len::<C>(LED_COUNT, SPI_HZ)` is a `const fn`, so the array is sized at compile time, and an unusable clock is a build error.
- **The DotStar output needs no buffer.** Clocked chips tolerate gaps, so `ClockedSpi` streams the frame through a 64-byte stack chunk. It has one frame writer for every path (Strip and smart-leds). That writer is checked against `wire::clocked_frame` byte for byte, so the two can't drift apart.
- **The wrong kind of chip doesn't compile.** `ClocklessSpi::new` evaluates `const { ClocklessTiming::of::<C>() }`, and `ClockedSpi::new` asserts `Protocol::Clocked` in a `const` block. `compile_fail` doctests prove both.
- **Every write ends with `flush()`,** so `show()` returns only after the bus is idle and the trailing reset zeros have gone out. That reset satisfies the reset gap between consecutive `show()` calls.
- **One error type:** `ledkit_spi::Error<E> { Spi(E), BufferTooSmall(BufferTooSmall) }`.
- **First light is the ESP32-C6 DevKit's onboard RGB LED** (WS2812-compatible, GRB, GPIO8; a strip of 1), driven from SPI2's MOSI routed to GPIO8 through the GPIO matrix. It's the only hardware on the owner's desk today, and it exercises the whole path: chip timing, byte-aligned encoding, color order, brightness and dithering.
- **Deferred, and recorded in the roadmap by Task 7:**
  - **Teensy 4 example:** needs the board and a strip on hand.
  - **APA102/SK9822 hardware check:** no DotStars on hand.
  - **`MAX_CLOCK_HZ` for clocked chips:** a wrong limit is worse than none until it's measured; the docs recommend 8 MHz or less for now.
  - **`defmt` support:** wait for the first Embassy example.

## Review Focus

1. **The HAL rounds the SPI clock.** If a user asks for 3.2 MHz and the bus runs at 3.15 or 3.25 MHz, the strip must still work. Task 1 tests that the byte-aligned WS2812B encoding at 3.15 and 3.25 MHz is the same 4-bit pattern as at 3.2 MHz.
2. **A blocking bus leaves gaps between bytes.** The default constructor must only produce bytes whose last bit is low. Task 1 checks this as a property over the whole 1–40 MHz grid for every clockless chip.
3. **The strip is bigger than the buffer.** The user gets a clear `Error::BufferTooSmall { needed }`, nothing is sent, and nothing panics. Tested in Task 2.
4. **The wrong kind of chip.** A DotStar chip on `ClocklessSpi`, or a NeoPixel chip on `ClockedSpi`, fails to compile. `compile_fail` doctests in Tasks 2 and 4.
5. **Zero LEDs** (`Strip<_, 0, _>` or an empty smart-leds iterator). This sends just the lead-in and reset (clockless) or the start and end frames (clocked), without panicking. Tested in Tasks 2, 4 and 5.

**Files:**

**Interfaces:**
- Produces: `ClocklessTiming::spi_encoding_byte_aligned(&self, spi_hz: u32) -> Result<SpiEncoding, TimingError>` (`const fn`). It has the same contract as `spi_encoding`, but only patterns with `bits_per_led_bit` of 4 or 8 qualify, and the `SpiClockUnusable` suggestions are byte-aligned clocks too.
- Produces: `SpiEncoding::encode_from_iter(&self, wire: impl IntoIterator<Item = u8>, out: &mut [u8]) -> Result<usize, BufferTooSmall>`. For any iterator it gives the same bytes and length as `encode`, without needing the length up front. If `out` runs out, it keeps counting the remaining input and returns `BufferTooSmall { needed: self.buffer_len(total_wire_bytes) }`; `out`'s contents are unspecified in that case.
